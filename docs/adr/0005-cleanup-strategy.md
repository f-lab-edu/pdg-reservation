# 0005. 저장소 초기화 방식

- 상태: 채택
- 날짜: 2026-11-01

## 맥락
- 컨테이너를 테스트 전체가 공유하므로 테스트 사이에 데이터가 남으면 서로 영향을 준다.
- DB, Redis, Kafka는 성격이 달라서 같은 방식으로 지울 수 없다.

## 결정
- **호출**: 각 테스트 클래스의 `@AfterEach`에서 **그 테스트가 사용하는 저장소만** 초기화한다.
- **DB**: `DatabaseCleanUp.truncateAllTables()`. 엔티티의 `@Table` 이름을 모은 뒤, 각 테이블에 `SELECT 1 ... LIMIT 1`로 행이 있는지 확인해서 **행이 있는 테이블만** 외래 키 검사를 끄고 `TRUNCATE`한 뒤 다시 켠다. 정리할 테이블이 없으면 아무것도 실행하지 않는다. 검사 설정이 연결 단위라서 `@Transactional`로 같은 연결을 쓰게 한다.
  - 처음에는 엔티티 테이블 10개를 매번 전부 `TRUNCATE`했다. MySQL의 `TRUNCATE`는 DDL이라 빈 테이블도 한 번에 약 100ms가 들어서, 테스트마다 정리에만 0.75~1.56초(가입 명세 53개 측정)가 걸렸다. 검증만 하고 끝나는 400 테스트도 약 0.85초였다. 강의의 H2는 메모리 DB라 이 비용이 거의 없다.
  - 행이 있는 테이블만 `TRUNCATE`하도록 바꾼 뒤 같은 53개 테스트의 개별 테스트 시간 합이 70.7초에서 5.4초로, 평균이 1.33초에서 0.10초로 줄었다. 검증만 하고 끝나는 테스트는 0.02초대다. 가장 느린 것은 첫 테스트(1.3초, 예열)와 실제로 가입이 저장되는 테스트(0.8초)다.
- **Redis**: `RedisCleanUp.flushAll()`. `FLUSHALL`로 전체를 지우고, 블룸 필터 설정도 같이 지워지므로 `AccommodationBloomFilter.init()`으로 빈 필터를 다시 만든다. 로그인처럼 Redis를 쓰는 테스트에서 추가한다.
- **블룸 필터**: 숙소를 만드는 Fixture는 저장 후 `bloomFilter.add(id)`를 한다.
- **Kafka**: 비우지 않는다. 비동기 처리가 끝나는 흐름은 Awaitility로 결과를 기다린 뒤 테스트를 끝낸다.

## 검토한 대안
- `@BeforeEach`에서 초기화: 이전 테스트가 정리를 빠뜨린 상태로도 시작할 수 있지만, `@AfterEach`로 정했다.
- Redis 키 접두사별 삭제(블룸 필터 키 제외): 지울 키 이름을 전부 알아야 하고 Redisson 내부 키 이름에 기대게 된다.
- 전체 테이블을 매번 `TRUNCATE`: 단순하지만 위 측정처럼 테스트마다 약 1초가 든다.
- `TRUNCATE` 대신 `DELETE FROM`: 행이 적으면 빠를 수 있지만 측정하지 않았고, 대량 데이터를 넣는 테스트가 생기면 `DELETE`는 느려진다. 행이 있는 테이블만 `TRUNCATE`하는 쪽이 둘 다 감당한다.
- 테스트마다 정리할 테이블을 직접 지정: 누락하면 데이터가 남아 테스트가 가끔 깨지고, API가 다른 테이블에 남기는 부수 효과(아웃박스 등)를 놓친다. 자동 검사가 사람이 목록을 관리하지 않아도 되어서 채택했다.
- `information_schema.TABLES.TABLE_ROWS`나 `AUTO_INCREMENT` 값으로 판단: InnoDB에서는 추정치거나 롤백된 INSERT에 어긋나서 정리를 건너뛸 위험이 있다.
- Kafka 토픽 삭제·재생성: 재시도 토픽과 컨슈머 그룹이 불안정하고 느리다.
- 테스트마다 컨테이너 재기동: 너무 느리다.

## 결과
- 테이블 수만큼 행 확인 쿼리(`SELECT 1 ... LIMIT 1`)가 나간다. 일반 SELECT라 DDL보다 훨씬 싸지만, 테이블이 크게 늘면 한 번의 쿼리로 묶는 것(`UNION ALL`)을 고려한다.
- 정리를 호출하지 않는 클래스가 있으면 상태가 다음 클래스로 새어 나간다. 부담이 되면 JUnit 확장으로 자동 실행한다.
- 이전 테스트의 Kafka 소비가 늦게 DB를 건드릴 수 있다. 흔들리면 컨슈머 랙 대기 도우미를 추가한다.
- 결제 대기 키의 만료 리스너(`ReservationTimeoutListener`)는 설계를 바꿀 예정이라 지금은 다루지 않는다.
